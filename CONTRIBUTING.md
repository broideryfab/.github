# Contributing to BroideryFab open source

Thanks for helping. These guidelines apply to all public BroideryFab
repositories unless a repository has its own `CONTRIBUTING.md`.

## Reporting issues

- Search existing issues first.
- For a file that parses incorrectly, include the format, the software or
  machine that produced it, what you expected and what you got.
- Attach a sample file **only if you have the right to share it publicly**
  (you created it, or its license allows redistribution). Do not attach
  purchased or customer designs.

## Pull requests

- Keep changes focused; one topic per pull request.
- Describe what changed and how you verified it.
- By contributing, you agree your contribution is licensed under the
  repository's license.

## Clean-room rule

Contributions must be your own work, written from format knowledge,
documentation and observation of files. **Do not copy or translate code from
GPL/AGPL or other copyleft projects**, and do not submit material from
proprietary SDKs or documentation you are not allowed to share. If you used a
reference, name it in the pull request.

## Conduct

Be respectful and constructive. Harassment or abusive behavior is not
tolerated; maintainers may remove comments or contributors that violate this.
